UltraLink

An Android application connecting Bluetooth media transfer, image annotation and conversations around point-of-care ultrasound.

The idea

Portable ultrasound can bring imaging closer to the point of care. UltraLink explored how a clinician could obtain an image, mark the areas worth discussing and share it with another clinician in the same mobile application.

We organised the project around three interactions: acquiring media from a device, working with the image, and discussing it with another person.

My contribution

I implemented Bluetooth transfer, image editing, the initial Firebase connection and storage integration, and the gallery of previous images. I also worked on the main page and changed image sharing in chat so that the actual image appears inside the conversation and can be opened directly.

I developed the application with Tiago, using Git to coordinate our work.

From acquisition to conversation

The main page connects Bluetooth acquisition and local media selection to the editors. The Bluetooth flow discovers devices, establishes a connection and transfers text, images or videos, with progress feedback while receiving media.

In the image editor, users can draw, erase, add draggable text and shapes, change annotation sizes and crop the image. The resulting composition can be saved or shared. The video editor adds playback, clip selection and trimming, plus frame extraction into the image editor.

Firebase-backed conversations support messages and shared media. Images appear inline, and video thumbnails lead back to the editor. A separate gallery retrieves previously saved media associated with the signed-in user.

How it fits together

The application uses Java and Android XML layouts. Firebase Authentication handles accounts, Cloud Firestore holds profiles, conversations and media associations, and Firebase Storage holds uploaded files. Glide loads image previews, uCrop supports cropping, and Media3 and FFmpeg support the video workflow.

The Bluetooth service uses client and server socket threads and a custom protocol that sends content type and length information before the payload. The acquisition screen receives progress and completion events, saves the file and opens the appropriate editor. A compatible peer must use the same protocol.

This project brought together device communication, interactive image manipulation and asynchronous cloud operations. Connecting these pieces meant carrying the right file, user and conversation context between screens while keeping local files and uploaded media in sync.

Scope & code

UltraLink is an academic prototype built around an ultrasound-sharing use case. The repository contains a generic Bluetooth transport rather than a vendor-specific ultrasound SDK; the hardware used for transfer testing is not documented here.

A next development pass would focus on interrupted-transfer recovery, Android-version compatibility and backend access rules. The notification sender also needs to move to a trusted backend before deployment. These are distinct from the implemented editing, gallery and chat flows.
