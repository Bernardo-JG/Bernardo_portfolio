The idea

I built a local tool to make second-hand computer-component listings easier to compare. A scan collects configured OLX searches, updates an SQLite database and opens an HTML report with potential deals, the cheapest listings in each comparison group, and search and category filters.

The current application uses only Python’s standard library. It runs on demand, with no web server or background scheduler, and keeps its observations locally.

Collection & comparison

The workflow separates collection, text classification, storage and reporting. Stable OLX listing IDs prevent repeated scans or different URLs from duplicating the same advert. The database preserves first/last-seen information and records a price-history entry only when a listing is new or its price changes.

Comparisons use the latest price for each advert observed within the last 30 days. Groups separate model and relevant specifications, plus new/used condition. A median requires at least four comparable adverts; the default shortlist highlights prices at or below 80% of that median. Cheapest-list views remain useful before enough observations exist for a median.

Handling messy data

Recognition is based on normalised listing text. For example, a Ryzen 5600 and an RX 5600 XT belong to different categories, while a bare ambiguous “5600” is left unclassified. GPU memory variants and RAM capacity, module layout, speed and form factor help keep unlike items out of the same comparison.

Complete PCs and component bundles are filtered out. Explicit defect wording is flagged and excluded from medians, while untested items remain eligible. The report shows capped searches, failed queries and recognised-listing counts rather than hiding incomplete collection.

The repository includes ten regression tests covering recognition edge cases, deduplication, price history, database migration, report escaping and partial collection failures. All ten passed during the documentation review; this does not test the live OLX service.

What the numbers mean

These are observed asking prices, not completed sales or verified resale opportunities. Searches have bounded coverage, matching is heuristic, and an advert disappearing from a scan does not establish that it sold. Delivery costs, seller reliability and component condition still require manual review.

The project made data quality a central design concern: a useful comparison depends as much on recognising comparable products and explaining missing observations as on calculating a median.
